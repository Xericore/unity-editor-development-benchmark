# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Unity project used to develop and dogfood a single Unity Editor package: **`com.xericore.unityeditordevelopmentbenchmark`** ("Unity Editor Development Benchmark") — a tool that measures how much time a developer spends waiting on the Unity Editor (compilation, domain reload, asset import, play mode switches, builds, editor startup, lightmap baking).

All product code lives under `Packages/com.xericore.unityeditordevelopmentbenchmark/`. The `Assets/` folder is just a sandbox scene for manually exercising the package inside the editor — it is not the product.

## Working with this codebase

There is no CLI build, lint, or test suite — this is a Unity Editor project. To make changes and verify them, open the project in **Unity Editor 2022.3.62f1** (see `ProjectSettings/ProjectVersion.txt`) and let Unity recompile; the `.csproj`/`.sln` files at the repo root are auto-generated by the Rider package (`com.unity.ide.rider`) and should not be hand-edited.

To exercise the tool manually, use the editor menu **Window > Analysis > User Wait Time Tracker** (`UserWaitTimeEditorWindow`), which shows the live table this package produces.

This package targets Unity 2022.3 per `package.json`, but is written to also run correctly on other host Unity versions once published — see "Version-guarded APIs" below.

## Architecture

### Tracker pipeline

- **`UserWaitTimeTrackerBase`** (abstract, `Editor/UserWaitTimeTrackers/`) is the base class for every tracker. It exposes a `UserWaited` event, persists `LastWaitTime`/`TotalWaitTime` per-tracker via `EditorPrefs` (keyed by `GetType().Name`, so **totals are global across all Unity projects on the machine**, not per-project), and is driven by subclasses calling `ReportSingleWaitEvent(TimeSpan)`.
- Each concrete tracker (`CompilationUserWaitTimeTracker`, `DomainReloadUserWaitTimeTracker`, `AssetImportUserWaitTimeTracker`, `SwitchPlayModeUserWaitTimeTracker`, `BuildUserWaitTimeTracker`, `EditorStartupUserWaitTimeTracker`, `LightmapBakingUserWaitTimeTracker`) wraps a corresponding static utility in `Editor/Util/` that hooks the actual Unity Editor API/event (e.g. `LightmapBakeTimeUtil` wraps `Lightmapping.bakeStarted`/`bakeCompleted`, `MyAssetPostprocessor` wraps `AssetPostprocessor` callbacks, `AssemblyReloadTimer` wraps `AssemblyReloadEvents`). Trackers translate the raw utility events into `ReportSingleWaitEvent` calls.
- **`UserWaitTimeAggregator`** (`[InitializeOnLoad]`, static) owns one instance of every tracker, in a fixed field-declaration order, and wires up their `UserWaited` events to a single `AnyWaitEventFired` event. Trackers are instantiated here (not each self-registering via its own `[InitializeOnLoad]`) specifically to guarantee initialization order, since `[InitializeOnLoad]` alone gives no ordering guarantee across classes and the abstract base class can't itself carry the attribute.
- `UserWaitTimeAggregator.GetWaitTimeData()` returns a `List<UserWaitTimeData>`, one row per tracker plus a synthesized "Total since <reset time>" row; `ResetTotalWaitTime()` resets every tracker plus the last-reset timestamp (also `EditorPrefs`-backed).
- **`UserWaitTimeEditorWindow`** renders that list as a UIElements `MultiColumnListView` (category, total time, ratio, progress bar, last wait time) and rebuilds on `AnyWaitEventFired`.

### Compilation timing detail (`Editor/Serialization/`, `MyCompliationData.cs`)

Compilation/domain-reload timing needs finer-grained data than Unity's public events expose, so `CompilationData` (in `MyCompliationData.cs` — filename typo is intentional/existing, don't "fix" it as an unrelated rename) parses Unity's internal Bee build system profiler trace at `Library/Bee/fullprofile.json` (`Library/Bee/profiler.json` on older Unity) via `BeeProfilerData`/`TraceData`/`AssemblyCompilationData`, cross-references it against `TraceData.instance` timestamps, and reconstructs accurate per-assembly `Csc` compilation spans. `AssemblyReloadTimer` (in `Util/`) calls this ~1s after `AssemblyReloadEvents.afterAssemblyReload` (via UniTask) to let the Bee trace file finish being written before reading it.

### Version-guarded APIs

Several files branch on Unity version via preprocessor symbols because the package must run across Unity versions even though the sandbox project pins 2022.3.62f1:
- `LightmapBakeTimeUtil`: only hooks `Lightmapping.bakeCancelled` under `UNITY_2023_1_OR_NEWER` (not available earlier).
- `MyCompliationData.cs`: switches the Bee profiler JSON path and a trace-event filter (`pid != "0"`) under `UNITY_2021_2_OR_NEWER`.

When touching editor-event integrations, check whether the underlying Unity API differs across supported versions before assuming a fix generalizes.

### Conventions

- Namespace root is `UnityEditorDevelopmentBenchmark`; the package assembly is `UnityEditorDevelopmentBenchmark.Editor` (editor-only asmdef, see `Editor/UnityEditorDevelopmentBenchmark.Editor.asmdef`).
- Private fields are `_camelCase`; per `.editorconfig`, 4-space indent, CRLF line endings.
- Package dependencies (`com.cysharp.unitask`, `com.needle.compilation-visualizer`, `com.unity.ide.rider`) come from the `package.openupm.com` scoped registry declared in `Packages/manifest.json`.

### Not part of the package

`Assets/TimeWaster/` is a separate, unrelated personal tool (a scene-view "time wasted compiling" overlay) that is explicitly excluded via `.gitignore` (`/Assets/TimeWaster`) — it exists locally but is not tracked in git and is not part of this package. Don't assume it ships or is referenced by the package code.
